# Программный комплекс глобальной оптимизации с нелинейными ограничениями

Данный репозиторий содержит программный фреймворк на C++ для решения задач многомерной глобальной условной оптимизации. В проекте реализованы информационно-статистические алгоритмы (школа проф. Р.Г. Стронгина) с применением редукции размерности на базе кривых Пеано, а также интегрирован детерминированный алгоритм DIRECT-G (метод штрафных функций) для сравнительного анализа.

Особое внимание в проекте уделено разработке и тестированию **Многомерного индексного метода с локальным уточнением (MIML)**, который эффективно преодолевает нелинейные штрафные барьеры.

## 🚀 Подробный функционал комплекса

Программный комплекс обладает масштабируемой модульной архитектурой и включает в себя следующие ключевые подсистемы:

### 1. Ядро информационно-статистической оптимизации (MIM и MIML)
*   **Индексная схема учета ограничений:** Алгоритм не использует аддитивные штрафы. Целевая функция и функции ограничений структурно разделены и обрабатываются как единая последовательность разрывных испытаний.
*   **Механизм $\epsilon$-резервирования:** Позволяет алгоритму уверенно работать в случаях, когда истинный глобальный оптимум лежит строго на границе допустимой области, предотвращая преждевременную отбраковку перспективных точек.
*   **Локальное уточнение (MIML):** Авторская модификация, преодолевающая топологические искажения кривой Пеано. Алгоритм динамически оценивает близость интервала к текущему рекорду (метрика $\delta_i$) и адаптивно модифицирует поисковую характеристику $R_\alpha(i)$. Это обеспечивает форсированное стягивание испытаний на дно найденного экстремума. Реализована гибкая система настройки гиперпараметров (интенсивность сгущения $\alpha$, отложенный старт `delay`, баланс глобальных и локальных шагов).
*   **Редукция размерности:** Сведение многомерной задачи к одномерной посредством непрерывных однозначных разверток (аппроксимация кривой Гильберта-Пеано 12-го порядка) с корректным пересчетом констант Липшица в гёльдерову метрику.

### 2. Вычислительная оптимизация структур данных ($O(N)$)
*   **Инкрементальное кэширование констант Гёльдера:** Классическая формула оценки $\mu_\nu$ требует попарного сравнения всех точек, что дает сложность $O(N^2)$ и делает алгоритм неработоспособным при $N > 10~000$. В ядре реализовано инкрементальное обновление максимумов через ассоциативные словари `std::map`. 
*   **Cache-friendly архитектура:** Хранение истории испытаний осуществляется в непрерывных участках памяти (`std::vector`), что минимизирует промахи кэша процессора и снижает итоговую сложность одной итерации до строгого $O(N)$.

### 3. Расширенный генератор тестовых сред
*   **Авторские алгоритмы топологических сдвигов:** Оригинальная библиотека `GcGen` (модель GKLS) доработана для создания сложных условных сценариев:
    *   `OnBorder`: Алгоритм выпускает лучи из точки оптимума, находит ближайшее пересечение с нелинейным ограничением и транслирует всю гиперповерхность ограничения так, чтобы оптимум оказался строго на границе.
    *   `OutDomain`: Оптимум искусственно выталкивается за пределы допустимой зоны, формируя сложный нелинейный овраг на стыке ограничений.


### 4. Интеграция и верификация с DIRECT-G
*   Подключена оригинальная C-библиотека алгоритма DIRECT-G (метод Яблонски).
*   **Внешний квадратичный штраф:** Реализована функция-обертка для применения DIRECT к задачам с ограничениями.
*   **Единый координатный критерий остановки:** Для обеспечения абсолютной академической честности при сравнении методов с разной логикой, внедрен принудительный триггер `force_stop`. И DIRECT, и индексные методы останавливаются строго в момент физического попадания сгенерированной точки в $\epsilon$-окрестность истинного условного оптимума. Встроен режим «строгого бюджета» (debug) для отключения ранней остановки и выявления феномена ложной сходимости.

### 5. Инфраструктура автоматизированного тестирования
*   **Стенд массовых запусков:** Поддержка серийного тестирования (например, на 100 случайных задачах подряд) с автоматической агрегацией статистики (итерации, вычисления, время в мс) в файлы `stats.txt` и `graphics.txt`.
*   **Система фильтрации:** Поддержка файла `custom_tasks.txt` для исключения математически вырожденных задач и формирования жестких, репрезентативных выборок.
*   **Python-визуализация:** Автоматическая генерация аналитических графиков через `matplotlib`.
    *   *В 1D:* Отрисовка целевой функции, графиков ограничений, заливка недопустимых (красных) зон и точечная визуализация всей истории испытаний.
    *   *В 2D:* Построение тепловых карт (contour lines), отрисовка границ нелинейных ограничений (эллипсы, синусоиды), цветовая дифференциация допустимых и недопустимых испытаний.

## 🧮 Поддерживаемые классы задач

Интерактивное консольное меню позволяет выбрать следующие типы задач:
1. **Unconstrained Hill/Shekel:** Безусловная 1D-оптимизация.
2. **Grishagin:** Двумерные мультимодальные тестовые функции Гришагина.
3. **Example 3.2 (1D):** Классическая аналитическая задача с тремя нелинейными ограничениями (иллюстрация «пробоя» штрафного барьера).
4. **OptSqConstr1D:** Базовая квадратичная задача для калибровки.
5. **Custom Constrained Problem:** Комбинированные 1D задачи (целевая функция Шекеля + ограничения Хилла).
6. **Example 5.1 (2D):** Сложная двумерная задача со сложной геометрией ограничений (круг, эллипс, синусоида) и экспоненциальными впадинами.
7. **GKLS Multidimensional Constrained:** Серийные запуски на 100 случайных многомерных задачах (сценарии `InDomain`, `OnBorder`, `OutDomain`).

## 🛠 Сборка проекта

### Требования:
* Компилятор с поддержкой **C++17** (GCC, Clang или MSVC).
* **CMake** версии 3.10 или выше.
* Установленный **Python 3** с библиотеками `matplotlib`, `numpy`, `scipy` (только для отрисовки графиков).

### Инструкция по сборке (Linux / macOS / Windows Git Bash):
```bash
# 1. Клонирование репозитория
git clone https://github.com/Applejack2004/Strongin_global_method.git
cd Strongin_global_method

# 2. Создание папки для сборки
mkdir build && cd build

# 3. Конфигурация и сборка
cmake -DCMAKE_BUILD_TYPE=Release ..
cmake --build .
```

## 🖥 Использование

После сборки запустите исполняемый файл `OptimizationProject` (в Windows — `OptimizationProject.exe`).

Программа предложит интерактивное меню настройки:
1. Задать параметр надежности $r$ (например, `3.0`).
2. Задать точность $\epsilon$ (например, `0.001`).
3. Задать лимит итераций (например, `10000`).
4. **Strict budget mode:** Выбор режима отладки (отключение ранней остановки для проверки ложной сходимости DIRECT-G).
5. Выбор алгоритма (Стронгин / DIRECT-G). При выборе метода Стронгина можно включить локализацию **MIML** и задать её гиперпараметры (delay, $\alpha$, ratio).
6. Выбор класса задачи.

В процессе работы программа выводит статистику в консоль и генерирует текстовые логи (`trial_points.txt`, `function_plot_data.txt`). 

### Визуализация
Если при запуске серийных тестов выбрать режим `silent`, программа автоматически вызовет Python-скрипты, которые сгенерируют PNG-изображения графиков и сохранят их в папку `plots_output/`. 

Вы также можете запустить скрипты вручную из директории сборки:
```bash
python ../plot_1d_constrained.py
python ../plot_gkls_2d.py
```
